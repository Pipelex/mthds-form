# Derivation-swap review — deferred follow-ups

Surfaced while verifying the review-bot findings on the derivation-swap PR (PR #11). None of these is a bot thread: the threads were all either fixed or resolved on that PR. These are adjacent facts the verification established that did not meet the bar for fixing in that round — recorded here so they are decisions, not omissions.

## 1. `date` and `enum` kinds carry no `contentKey`

`derive.ts` stamps `contentKey` on the text/prose, number and boolean arms only; the `date` and `enum` arms never read `scalarWrapperKey`, and `toRjsf` falls through to `default: return value` for both. A top-level `date`- or `enum`-kind slot over a single-property wrapping content model would therefore send the bare scalar where the schema wants an object.

Why deferred: believed unreachable today — `native.Date` is an `object` node over `DateContent {date, time}` (pinned in `concept-taxonomy-characterization.test.ts`), and date/enum nodes otherwise arise as bare-string structure fields. And unlike the text case that was fixed, the write path is also unwrapped, so the failure mode is a loud gate rejection, never silent data loss. If a wire ever pairs those kinds with a wrapper model, give both arms the same `contentKey` treatment as the other scalars.

## 2. Pre-existing: very deep ref-free schemas overflow before the gate walk

A deeply nested (thousands of levels) inline schema makes `buildRunInputsSchema` throw `RangeError` out of `normalizeSchemaForRjsf` / `walkAndCollectDefs` (`normalize-schema.ts`, `schema-utils.ts`) — uncapped recursion over `properties`, hit before the gate's own tree walk even runs. So `gateRunInputs` is still not total over pathological contract shapes, even after the cycle guard: the recursive-schema fix closed the unbounded case (a cycle has no floor at all); this one is bounded by the document, merely deeper than the stack.

Why deferred: pre-existing (predates the derivation swap), producer-reachable only (the contract comes from the server-held method, not the request body), and no MTHDS producer emits nesting anywhere near stack depth. A fix would be an explicit-stack rewrite or a depth cap in the normalize walk; decide when a real producer gets within an order of magnitude of the limit.

## 3. Pre-existing: `resolveSchemaIndirection` loops forever on a self-referential definition

`resolveSchemaIndirection` (`schema-utils.ts`) resolves with an unbounded `for (;;)`: a `$defs` entry that resolves to itself (directly or through a nullable `anyOf`) hangs it. Its callers are `healStringWrappers` and `pruneEmptyOptionals` (`wire-format.ts`), whose outer recursion is data-bounded — but the per-node resolution is not. Same reachability profile as item 2: producer-only, and today's producers do not emit recursive structures.

Why deferred: same round-bar reasoning as item 2, and the fix should not change the function's replace semantics (characterized in `schema-utils-characterization.test.ts`). A hop cap like `resolveSchemaNode`'s is the likely shape if it is ever needed.

## 4. The gate's cycle guard loses required-child blankness checks at recursion depth ≥ 1

Deferred from PR #11 review round 2. Threads: [greptile P1](https://github.com/Pipelex/mthds-form/pull/11#discussion_r3876454574) and [codex P2](https://github.com/Pipelex/mthds-form/pull/11#discussion_r3876458226), both on `gating-fields.ts` — one deduped issue, verdict **confirmed** (reproduced against the built kernel).

When the per-path cycle guard in `gatingFieldsFromInputs`'s walk (`gating-fields.ts`) meets a `$ref` already open on the path, the node degrades to the opaque `unknown` leaf, and `fieldFilled` answers an `unknown` node with `isFilled` alone (`readiness.ts`). So required-child blankness checks vanish *below the cycle point* — the top level of a recursive definition still expands once in full and is checked normally. Reproduction: a contract for `TreeNode {label: str, children: list[TreeNode]}` with **both properties required**; `gateRunInputs` returns `ok: true` on `{tree: {label: 'root', children: [{label: '', children: [{label: 'kid', children: []}]}]}}` — ajv accepts the blank `label` (presence is all `required` asserts, and a content model carries no `minLength`), and the emptiness re-check cannot see it behind the opaque leaf. That violates the rule `gate-agreement.test.ts` pins one level up: a started list row owes its concept every required child.

Why deferred (round-2 bar): **not a regression** — before the cycle guard landed, the same contract made `gateRunInputs` throw `RangeError`; the guard turned a crash into a slightly-permissive verdict, and the `unknown` leniency class predates it (it was already the walk's terminal for non-object/non-array schemas). **Not a blocker** — the schema is the server-held contract's, not caller-controlled; no MTHDS producer emits recursive concept structures today (same reachability profile as items 2 and 3); the browser is the stricter side, so no user reaches it through the UI; what gets through is a schema-valid payload carrying a blank string. Note also that the claimed gate/browser *disagreement* is producer-dependent: the wire input-form descriptor has no reference mechanism, so a producer meeting a recursive concept must truncate, and the two sides disagree only if it truncates deeper than one level. If it emits the `unknown`-item escape hatch at the first recursion, gate and browser agree exactly and there is nothing to fix.

If it is ever fixed, the only correct shape is **data-bounded re-expansion**, not "retain/lazily apply the referenced node's checks" as the bots suggest — a finite eager tree can never agree with a schema of unbounded depth, so that phrasing has no terminating implementation. Thread the input value into the walk and, at the cycle point, re-expand the referenced node only while the data still has something at that position: termination is free (the data is finite and `isFilled`'s depth cap bounds it), and the signature change is contained because `gatingFieldsFromInputs` is package-private (sole caller in `gate.ts`, absent from `src/core/index.ts`). Two alternatives considered and rejected: a bounded re-expansion budget (a `Map<string, number>` in place of the path set) only moves the boundary deeper without restoring agreement, and failing *closed* at the cycle would refuse every legitimate recursive payload — a worse defect than the leniency it fixes.

Test approach when taken (red first): beside the existing `'a schema that references itself'` block in `hostile-values.test.ts`, add a `TREE_REQUIRED` fixture identical to its `TREE` but with `required: ['label', 'children']`, and assert the gate refuses the payload above (today it approves it). Pair it with the existing `TWINS` case so the fix cannot be a blanket un-guarding. Hold the `gate-agreement.test.ts` half until the standard settles how a producer truncates a recursive concept in the descriptor — pinning it earlier would pin a descriptor shape this package invented.
