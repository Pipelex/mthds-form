# Wording a form for its reader

A form built from a method speaks two vocabularies. The controls' own copy — "Add item", "optional", "Drop a file or click to browse" — belongs to this package. The field labels, helper lines and enum choices come from the method, written by its author, in its author's language and often as identifiers (`display_name`, `PARIS_15`). A host serving a French page, or a page for people who have never seen the method, needs both in its reader's words. The package gives it one seam for each.

## The controls' copy: `FieldStrings`

Every string a control renders comes through `FieldStrings`, with complete English defaults (`DEFAULT_FIELD_STRINGS`). A host mounts `FieldStringsProvider` above the form with a partial or complete set, merged over the defaults. Count-bearing messages are functions rather than templates, so each locale applies its own plural rules.

`FR_FIELD_STRINGS` is a complete French set, exported from `./react` for a host that has no catalogue of its own to bridge. It applies French plural rules (zero and one take the singular: `0 élément`, `1 élément`, `2 éléments`), writes a file size as `36 ko` or `1,4 Mo`, and puts a no-break space before a colon. Plurals and sizes come from the platform's `Intl` (`PluralRules('fr')`, `NumberFormat('fr-FR', { style: 'unit' })`) rather than hand-written rules. Locale packs live in `src/react/locales/`, one file per language (`fr.ts`); a new language is a new file there, exported from `./react` the same way. It is typed as a whole `FieldStrings`, so a key added to the contract fails the build until it is translated. A host that wants a different word for one key spreads it: `{ ...FR_FIELD_STRINGS, addItem: 'Ajouter une ligne' }`.

`describeValidationError` takes the host's own `Translate` over its `ValidationMessageKey`s. The package ships no message table for those keys in any language, English included, because they are namespaced in the host's catalogue (`inputPanel.*`); a French host adds the six keys to its own catalogue.

## The method's words: `applyFieldOverrides`

The method's words reach a control through fields the controls already read: `title` (the label, shown verbatim in both presentations), `description` (the helper line), `placeholder` (read by the `text` and `prose` controls) and, on an `enum` field, `optionLabels`. `applyFieldOverrides(fields, overrides, onUnmatched?)`, in the core entry, sets them per field over what the descriptor states, and returns a new tree:

```ts
const fields = applyFieldOverrides(buildRunFields(form, contract), {
  comment: { title: 'Commentaire', placeholder: 'Précisez la demande du client…' },
  'customer.display_name': { title: 'Nom du client' },
  'boutique.code': { title: 'Boutique', optionLabels: { LILLE: 'Lille', PARIS_15: 'Paris 15e' } },
  illustrations: { title: 'Illustrations', description: 'Photos du chantier' },
  'lines[].unit_price': { title: 'Prix unitaire' },
});
```

- **A path is field names joined by dots**, from the top-level input down through structures. A list is stepped into with `[]`, as `narrowFileFormats` names its paths: `illustrations` is the list itself, `illustrations[]` its item, and `lines[].unit_price` a field of every row's record. An override on a list's item therefore applies to every row alike.
- **Each key replaces only its own slot**, and only on a kind that reads it: a `placeholder` on a number or an `optionLabels` on a text field is ignored. An empty `title` is stated rather than absent, and hides the label as a list row's does. `optionLabels` merges over any labels the field already carries.
- **A path that names no field is ignored**, so a host's table can outlive a field its method dropped without breaking the form. Pass `onUnmatched` to be told each such path, to warn in development or to fail a test.
- **Nothing is mutated.** A field an override reaches, and the structures and lists above it, come back as copies; every other field comes back as the same object.

Like `narrowFileFormats`, it reads the kernel's own `RunField` and never a JSON Schema, so it touches neither of the two schema walks the package allows.

## Enum option labels

`optionLabels` maps an enum's codes to what a person reads (`{ LILLE: 'Lille (59)' }`). It is not a wire fact — the input-form descriptor carries the authored `choices` only — so a host sets it, usually through `applyFieldOverrides`. `EnumField`, the result view's value, its table cells and their tooltips all word a value through `enumLabeler`, which reads the labels first:

- A labelled option reads as labelled in **both** presentations, as an authored `title` does: someone chose those words for the page.
- An option the labels leave out reads as it would without them — its code in `studio`, its code in words in `app`, with the usual fallback to the codes when two options would read the same.
- A value the enum does not declare is shown as it came, labelled or not.
- Only what is shown changes. The form stores the code (`LILLE`), and the JSON view, the copy control and the download keep it.

The segmented control measures the label it shows, so a long label can turn a short enum into a select.

## Choosing the language per user

A host serving several languages passes the user's locale and lets the package pick the pack: `<FieldStringsProvider locale={user.locale}>`. `fieldStringsFor(locale)` reads the code as BCP 47 and keys on its primary language subtag, so `fr`, `fr-FR` and `fr_CA` all give French, and a missing or unknown locale gives English. `strings` still overrides single keys on top of the chosen pack: `<FieldStringsProvider locale="fr" strings={{ addItem: 'Ajouter une ligne' }}>`. The shipped packs are listed in `SUPPORTED_LOCALES` and `FIELD_STRINGS_BY_LOCALE`; English lives in `src/react/locales/en.ts` and stays exported as `DEFAULT_FIELD_STRINGS`.

To add a language, add `src/react/locales/<code>.ts` typed as a whole `FieldStrings` (the build fails until every key is translated), take plurals and sizes from `Intl` for that code, add it to `FIELD_STRINGS_BY_LOCALE` in `src/react/locales/index.ts`, and export it from `./react`.
