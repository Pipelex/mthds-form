# Changelog

## [Unreleased]

### Changed

- **Breaking: the input contract mirror follows the wire's reshaped `pipe_io_contracts`.** An input no longer carries a boolean `optional`; it carries the authored marker verbatim as `presence: 'plain' | 'optional' | 'force'`, alongside the `multiplicity: 'single' | 'variable' | 'fixed'` and `item_count: number | null` pair the wire now states. The output contract gained the same multiplicity pair and deliberately kept its boolean `optional` — output presence is genuinely two-valued, because `!` is rejected on an output.

  There is no compatibility branch, so a contract in the retired shape now reads as `plain` and every `?` input in it gates. That fails in the safe direction — a run is blocked, never mis-sent — but a host whose runtime has not yet moved will see optional inputs demanded until it does. `isOptionalInput` is the one predicate that answers "may this be absent?" for the whole package, so a host reading `input.optional` itself should call it instead of matching on the marker.

- **A fixed-count list (`Concept[N]`) gates like any other input.** A plural slot never blocked Run, on the grounds that its empty form IS the empty list and no method can declare "at least one" — which is exactly right for `Concept[]` and exactly wrong for `Concept[N]`, where the method has declared the count. Left ungated the failure was not strictness but silence: an absent property is one ajv never validates, so the run went out with the input missing altogether. The declared count itself is enforced by the schema the contract already carries (`minItems`/`maxItems`), not restated in the kernel.

### Added

- **`gateRunInputs(contract, data)` — the whole server-side gate as one call.** Hosts were assembling `buildRunInputsSchema` → `prepareRunInputs` → `validateRunInputs` → an emptiness check → `apiInputsFromSchemaData` themselves, and the emptiness step is where it goes wrong: there are four look-alike predicates and only two of them are the ones the Run button reads. The obvious pair, `inputMustBeFilled` + `isFilled`, agrees on every native concept and diverges on a structured one in *both* directions — accepting a half-filled struct the browser refuses, and rejecting a filled all-optional struct the browser accepts — so a host whose methods use only native concepts has no test that can catch either. `gateRunInputs` runs `computeReadiness`'s own two functions over the same derived fields, which makes the browser and server verdicts one invariant rather than two resemblances, and the package now asserts it by running both sides over one table of structured fixtures.

  It returns a discriminated verdict (`{ok: true, inputs}` or `{ok: false, missingInputs, errors, preparedData}`) rather than throwing, takes `data` as `unknown` because that is what arrives at a public endpoint, and caches one schema object per contract — ajv keys its compiled-schema cache on schema object identity and never evicts it, so rebuilding per call retains a validator per request. The four steps stay exported for a host that renders its own panel. New topic: [docs/run-gate.md](docs/run-gate.md).

- **`ListRunField.itemCount` and `maxItemCount` carry a list's declared bounds (`Concept[N]`).** Present exactly when the schema states them, absent for a variable `Concept[]` list. Read off the array schema's `minItems`/`maxItems` — the keywords ajv itself reads — rather than off the contract's `item_count`, which states the same number for a `[N]` slot.

  **Two fields rather than one**, because they are two facts and a `[N]` slot only makes them look interchangeable. `buildRunFields` also recurses into a structured concept's own schema, where an array property carries whatever bounds its model declared and may state one alone. A single number was read as a minimum by readiness and as a maximum by the control that stops offering **Add**, so a nested array told "at least two" was presented as a list of exactly two, with Add dead over a list the method lets you grow.

- **`isOptionalInput`, `isFixedCountInput`, and the `InputPresence` / `IOMultiplicity` types are exported.** The predicates are what the retired `input.optional` read becomes; exporting them keeps a host from re-deriving a gating rule the kernel already answers — the re-derivation being what this package exists to remove.

### Fixed

- **A required structured input whose concept demands no child is no longer offered and then refused.** Readiness answered such a structure by checking its required children alone, which is vacuously true over a value that is not there when there are none: an input declared `opts = "RunOptions"` — a concept whose properties are all optional — reported ready while untouched, so the Run button lit up, while the value bridge omitted the untouched structure like any other and the gate then rejected the run on the combined schema's `required` list. This is the surviving edge of the family v0.3.0 closed for *optional* structured inputs: the two halves of the kernel disagreeing about whether the input is there, with no host able to correct it from outside.

  `fieldFilled` now asks `isFilled` before descending, so the rule is stated once — a slot holds something, and then everything it demands inside is filled — and readiness calls an input present exactly when the bridge keeps it. The visible consequence is that a required structure has to be *touched*: the button stays dark until a value goes somewhere inside it, exactly as it does for an untouched required number, and a section opened and left blank is still absent because the disclosure is view state the value never sees. The same answer now holds for a required all-optional struct nested inside another one, where the vacuous reading was recursive.

- **A fixed-count list (`Concept[N]`) no longer reads ready while short.** Readiness answered emptiness only — "is there anything in the array?" — so a `[3]` slot holding two items lit the Run button and the gate then refused it on the very count the method had declared. Fail-closed, but the two halves were phrasing different rules. `fieldFilled` now reads the count off the descriptor and demands that many filled items, so a row added and left blank does not pass for one either.

- **A *touched* optional input is held to what its concept declares — on both surfaces.** Readiness skipped an optional input entirely, so a structured one the user had opened and half-filled kept the Run button live while the gate rejected the run on a required child — the same disagreement the demanded case had. An optional input now enters the reckoning the moment something is filled in it and leaves it when it is complete. The visible effect is on the readiness count a host displays: 3 of 3 while the optional is untouched, 3 of 4 once it is started, 4 of 4 once it is done.

  `gateRunInputs` now makes the same **selection**, which is the half that was missing: it shared `fieldFilled` and `mustBeFilled` with readiness but kept only the inputs the method *demands*, so the check a touched optional would have failed was never run on it. ajv cannot cover for that — a required child that is a plain string arrives as `''`, which satisfies `required` — and the payload builder would then have sent the input, since it tests the very same `isFilled`. So the browser refused a run the server accepted and started. The rule is now stated once: the gate holds to its concept exactly the inputs it is about to put on the wire, and nothing it will omit. A touched-incomplete optional is named in `missingInputs`, as readiness already named it.

- **The gate names a demanded input that is absent altogether.** The missing-input scan checked required *children* and skipped any input whose concept lists none, so the shape above was refused with nothing named and the caller could only quote ajv's own `must have required property 'opts'`. An input the method demands and the data does not carry is now reported by its variable name whatever its concept declares inside.

- **An upload no longer lands in the wrong list row.** A row was identified by its position at every level — the React key, the field ID, and nothing else — and a row could be removed while an upload targeting the list was still in flight. Removing an earlier row renumbers every row after it, so a file that resolved afterwards was written into whichever row had moved into that position: silently, with the form still looking correctly filled. On a batch method that is one candidate evaluated against another candidate's document. Removal is now blocked while a file is arriving anywhere in that list, read by ID prefix so an upload *inside* a row counts as well as a row that is one. **Add stays available**, because appending moves no existing row.

  The row's field ID stays positional, deliberately: it is a path, and a host writes an upload back with `setValueAtPath(values, id.split('.'), value)`. Handing out an opaque token instead would mean the kernel keeping a live token-to-position registry for that pure function to consult. Beside it, each row now carries a generated React key so removing one **moves** the survivors instead of renumbering them into each other — which used to carry a row's own state, a caret or an open URL toggle, onto its neighbour's value. New topic: [docs/upload-seam.md](docs/upload-seam.md).

- **A fixed-count list stops offering rows past its count, and a list that arrives over-full reads unfilled.** A `Concept[N]` slot let the user add an (N+1)th row, which ajv then refused on `maxItems`. The control now reads the upper bound to stop offering **Add** — deliberately `maxItemCount`, not the lower bound it used to read. Add is not the only way to get there, though: a restored draft, a host seeding values, or a bespoke surface calling these predicates over data it never rendered can all hand readiness a four-item `[3]` slot, and the button was live on it while ajv alone refused. `fieldFilled` now rejects that too. Calling it *missing* stretches the word a little, which is why it was left open before; the alternative is a browser and a server disagreeing about a run, and that is the thing this release says cannot happen. The items badge states the count it is working towards (`2 of 3 items`) rather than only what it holds, through a new `itemsCountOf` key on `FieldStrings` — a host injecting a partial string set is unaffected; one that builds the whole interface gains a member.

- **`uploadingIds` shuts every door into a value, not only the dropzone.** The "paste a URL instead" toggle and the URL input behind it read the ambient `disabled` alone and stayed live during an upload, so a user could paste a URL over a file that was still arriving — and a host that had deleted its own staleness tokens on the strength of the seam's guarantee could have a started, billed run abandoned client-side.

- **The file input has an accessible name, and it is the element that takes focus.** `FieldShell` picks its label element from `htmlFor`, and `FileField` was the one control in the set that passed none — so the field's title rendered as a `<div>` bound to nothing and the input's accessible name computed to the empty string. The second half is the one a one-line fix would have left open: react-dropzone puts the tab stop on a `role="presentation"` div and leaves the real input at `tabIndex: -1`, so the element a keyboard or voice-control user lands on had no role and no name either. The tab stop is now the `<input type="file">` itself — which already had exactly the right role and only ever lacked a name — with the focus ring drawn on the dropzone through `focus-within`. Giving the div a `role="button"` of its own was the alternative and was rejected: it would put a second named control in the accessibility tree for one value.

- **A file preview stops showing the file before last, and stops spinning when nothing needs resolving.** Three independent defects in one control, and the first was masking the second:
  - the preview-type sniff concatenated the filename and the URL into one string before matching an end-anchored extension, so the filename half could never match and a value with a good filename but an extension-less URL (an opaque storage id, a `data:` URL) was offered no preview at all. The two are now tested separately, and a `data:` URL's declared MIME type is read as well;
  - a `data:` URL counted as something needing `resolveUrl`, so a host that supplies no resolver got a spinner that never stopped over a value the browser could have painted immediately. `http(s):`, `data:` and `blob:` are used directly;
  - the object URL made at drop time won over the controlled value unconditionally and was cleared only by the control's own clear button, so a host writing a different file at the same path got a chip naming the new file over a preview showing the old one. The local preview is now bound to the value it belongs to and retires itself when the value moves on;
  - the **resolved** presigned URL was never given that same binding, so it was the twin of the defect above rather than a different one: an open preview moving between two storage URIs kept painting the file before last under the replacement's name, and stayed there until the next resolution landed — or permanently, if it never did. The resolution is now kept beside the URI it came from and used only while that URI is still the value's, which makes staleness impossible rather than brief; clearing it from an effect would still have painted one frame of the old file. A resolution that *fails* leaves the spinner rather than the previous file, and is caught instead of escaping as an unhandled rejection into the host's app.

- **`isFilled` answers instead of overflowing the stack on a deep or cyclic value.** It walked a caller-supplied value with no depth limit and no cycle guard, so a value a few thousand levels deep threw `RangeError` from inside a host's server gate — a gate whose whole contract is that it returns a verdict rather than throwing across a boundary that strips the message to an opaque digest in production. The schema was no protection: `prepareRunInputs` copies a property the schema does not declare straight through, so a key ajv never walks still reaches the predicate. The walk now stops at a depth cap and answers `false` there, which is the deliberate half — past the cap nothing can be told about what is down there, and an unanswerable absence fails closed like every other one in this package. Because branches combine with `some`, an over-deep branch loses only its own vote and a real value beside it still reads filled. The walk also keeps the objects it has already judged, which is a cycle guard and a memo at once, and turns a value shaped like a diamond chain from exponential into linear.

- **A string of nothing but whitespace no longer counts as a filled value.** `isFilled` tested `value === ''` alone, so `'   '` in a required text input lit the Run button, passed ajv — a content model carries no `minLength` — and reached the runtime. The function's own contract already said "not empty / blank"; it is now implemented. The knock-on is the one the surrounding code already wanted: a blank *optional* input is omitted from the payload as a real absence the method can branch on, rather than sent as a supplied empty string.

- **An input whose name collides with `Object.prototype` is read as empty when it is empty.** Every key this package indexes a record by — an input variable, a structure's property, a pipe code, a content key — is chosen by the method author, and the records are plain objects a host built. A bare `values[name]` therefore answered the inherited function rather than `undefined` for a name like `constructor` or `toString`, and `isFilled` had no branch that called a function empty: a required input reported ready while holding nothing, and no readiness line named it. Every such read now goes through one `ownProp` helper — in the control set as well as the kernel, which is where the last of them was: the object control passed each child its value by a bare index, so a prototype-named child handed a control an inherited function. A boolean child rendered its switch **ON** over a value that was not there, and a list child threw a `TypeError` that took the whole form down. Its readiness half was already right, because `isFilled` answers `false` for a function as a backstop for routes `ownProp` does not cover. ajv cannot close this from the schema side — its `required` compiles to `data.constructor === undefined`, which the inherited function satisfies — which is why it had to be closed in the kernel. The same read fixes `getPipeIOContract`, which returned the `Object` constructor for a prototype-named pipe code: a truthy non-contract that sailed through the `if (!contract)` guard hosts are shown writing, so a pipe that does not exist rendered as one taking no inputs.

- **The README quick-start called `getPipeIOContract` with its arguments swapped**, and destructured a `canRun` the readiness verdict does not have. The lookup takes contracts, domain, pipe code — and because the last two are both strings, a swap typechecks and then resolves anyway against a bare-code-keyed map, failing only against a namespaced one, far from the call. Both are corrected, with a note beside the example stating the order and what `computeReadiness` actually returns.

- **A host no longer ships the run gate's validator to the browser.** Importing a control, or any core value from a client component, pulled ajv into the client bundle — reported as **+131 KB gzip First Load JS** on a starter app, for code the browser never calls. Bundlers keep or drop whole modules, so a consumer could not import their way out of it: host-side import discipline was tried against this and measured at exactly zero effect.

  It had two independent causes, and fixing only the reported one moved nothing. The controls reached `isFilled` and the two date helpers through the `../core` barrel, which statically imports the gate, which imports ajv — so tsup put ajv in the chunk *both* entries load. The controls now take their types from the barrel (a type import is erased before bundling and costs nothing) and their values from the specific module, leaving the shared chunk three leaf files that import nothing at all. Underneath that, `dist/core/index.js` was itself a single bundled module carrying real code beside a top-level `import Ajv from 'ajv'`, so a host importing `isFilled` to fold a section or `setValueAtPath` to write back an upload — both perfectly ordinary in a client component — got the validator with it. The build now emits every core module as its own chunk, which leaves the `.` barrel a pure re-export a consumer's bundler can tree-shake, keeping only the chunks behind the exports actually used.

  **No API moved** — both entry points export exactly what they did, and the per-module files in `dist/core/` are build artifacts the `exports` map does not expose. Measured end to end on a host that imports controls *and* core values: 1,037 KB raw / 308 KB gzip of client chunks with ajv present, down to 806 KB / 242 KB with ajv absent. Three guards keep it there, since every part of this regresses silently: lint bans value imports of the barrel from `src/react/`, and `make assert-bundle` both walks each built entry's graph for banned packages (this is now also what enforces the React-free core) and asserts the `.` barrel carries no inline code — the last one being what catches a narrowed entry glob, which the graph checks cannot see. See [docs/dependency-budget.md](docs/dependency-budget.md) § "The chunk graph is part of the budget".

## [v0.3.0] - 2026-08-24

### Fixed

- **An optional structured input is runnable again when it is left alone.** An input declared `focus = "ExtractionFocus?"` could not be run without being filled in, which is the opposite of optional: the value bridge materialized a shell of empty children for a section nobody had opened, and the gate then judged that invented object against the concept's full schema and rejected the run for a missing required child. Readiness was right to ignore the input and the Run button was right to light up — the two halves of the kernel disagreed about whether the input was even there, and no host could correct it from outside. Any concept with a required field was unusable as an optional input, which is a shape a method reaches for constantly.

  An untouched structure now stays absent, exactly as an untouched number does, and the gate's own pruning drops an optional property that empties out — so the surface that renders through RJSF, where the bridge is not involved, is repaired by the same change. Emptiness is `isFilled` throughout, so readiness, the prune and the wire payload cannot disagree again. The touch that keeps a structure is a **value** in it, not a disclosure — opening the optional section is view state the kernel never sees — and once anything is filled the whole shell survives, empty children and all, so the concept's required fields fall due and still fail loudly. An empty list is untouched by all of this — a plural slot is never absent, and neither is an item inside one: an item is in the list because the user added it, so adding is the touch. Absence is what a singular slot expresses, which is why an empty row added to a list of structures still reaches the gate as an object — it validates when the item concept demands nothing, and names the missing child when it demands one.

  This is visible on the wire, and it is a fix rather than a wire change: the shape it replaces was rejected by the kernel's own gate, so there was no working behaviour to preserve.

- **A validation error names the field the method wrote, not the title pydantic gave it.** A blocked run read `must have required property 'Audience'` where the bundle declares `audience`, sending the user hunting for a field their method does not contain. Quoting the schema `title` is right in an RJSF form, where the title is the rendered label, and it is the one place the gate's validator now diverges from RJSF's error transform: this package labels a field by its identifier, so that is the name its errors quote.

- **A `native.Number` input is runnable again — it wraps into the content envelope its concept declares.** The form offered a proper number control, readiness was satisfied, Run lit up, and the gate then rejected the payload with `'<input>' must be object`: the value bridge sent the number bare while the contract declared `NumberContent {number}`. The two halves of the kernel disagreed about the same input, no host could correct it from outside, and any method taking a number was unrunnable through the package. A number now travels as `{number: 2}`, and the plural and optional cases behave the way they read — an untouched optional number stays absent rather than becoming an empty envelope that would fail the content model's own `required`.

  This is visible on the wire, and it is a fix rather than a wire change: the shape it replaces was rejected by the kernel's own gate, so there was no working behaviour to preserve. The recorded drift on `native.Date` is a different case and is untouched — see [docs/derivation-swap.md](docs/derivation-swap.md).

- **A `native.YesNo` input renders as a switch.** The taxonomy looked for a concept named `Boolean`, which MTHDS does not have, so `kind: 'boolean'` was unreachable from a real method and a yes/no input arrived as a nested card wrapping a lone switch. The wire shape is `{yes_no: …}` before and after; only the rendering changes.

- **A number's `minimum` / `maximum` reach the control.** They are declared on the wrapped property, never on the wrapper object, so reading the outer schema always found nothing and the stepper ignored a method's declared range.

### Changed

- **The scalar content wrapper is derived from the contract, not from a hand-kept list.** `buildRunFields` — still the only reader of JSON Schema — finds the single property a scalar concept's content model declares and stamps its name on the descriptor as `RunField.contentKey`; the value bridge wraps and unwraps by that name and no longer keeps a taxonomy of its own. That is what made the bug above possible: the render taxonomy knew `native.Number` and the wrapper taxonomy did not. Deriving the name covers a concept nobody remembered to add, instead of adding a fourth special case that would leave the next one uncovered.

- **The native-concept sets spell the codes the language actually defines.** `Integer` and `Float` were dead entries for concepts MTHDS has no such thing as, and `Boolean` was the miss above. `HTML_CONCEPTS` is the deliberate exception and stays misspelled: the language spells it `Html`, the set matches nothing a real contract carries, and `native.Html` therefore falls through to a nested card over `HtmlContent {inner_html, css_class}` that round-trips correctly. Correcting the spelling alone would break inputs that work today by routing them into the recorded `Date` drift, so it goes with that fix at the derivation swap.

## [v0.2.0] - 2026-08-21

### Added

- **A presentation seam on the controls — `FieldPresentationProvider`.** A form has two audiences and they want opposite label chrome. In a builder-facing surface the field's name IS the identifier written in the `.mthds` file, so it is shown verbatim in mono beside its concept pill; in a published method app that name and that concept are implementation detail the person filling the form has never seen. `presentation="app"` humanises the label (`full_name` → `Full name`), drops the pill, and outlines a field in error instead of only captioning it — the caption alone is easy to miss on a tall form, and on controls whose `aria-invalid` sits on an element the user cannot see (the file dropzone's hidden input, most of all) it was the only signal at all. `studio` is the default, so nothing changes for a host that says nothing.

  It is a context rather than a prop, deliberately: only the components that own label chrome read it — `FieldShell`, `ObjectField`, `BooleanField` and `ListField` — and a prop would have meant editing every control and both recursive containers to carry a value they never use. An authored `title` is preserved verbatim in both presentations; only the identifier fallback is humanised. `humanizeFieldName` is exported too, for hosts that label something outside a control.

## [v0.1.0] - 2026-08-21

The initial contents of the package.

### Added

- **The headless core (`.`)** — `buildRunFields`, the one derivation function turning a method's `pipe_io_contracts` into `RunField` descriptors; the `RunField` union itself; the run gate (`buildRunInputsSchema` → `prepareRunInputs` → `validateRunInputs` → `apiInputsFromSchemaData`); readiness; the typed `PipeIOContract` mirror with `getPipeIOContract` / `buildPipeRef`; store and wire value conversions; the wire format's deflate/inflate and its exactly-one-wrapper invariant; pydantic-parity date leniency; validation-error presentation; schema utilities.
- **The control set (`./react`)** — `FieldRenderer` dispatching one control per field kind, recursing for objects and lists; `FieldShell`, `ConceptPill` and `OptionalToggle`; `FieldStringsProvider` for host-supplied copy with complete English defaults; `FieldEnv` for injected upload handling.
- **Theming** — Tailwind classes over standard shadcn/ui semantic tokens, a prebuilt `styles.css` for hosts with no Tailwind build, and a `theme.css` of default token values.

### Changed, during the extraction

- **The gate no longer validates through RJSF.** It uses the package's own ajv instance, configured for the same pydantic-parity leniency, and reports a `RunInputError` the package owns. Error output was recorded against the previous implementation and proven identical on every fixture before the swap.
- **The nullable-`anyOf` collapse and the `$defs` walker are each stated once**, with the modes their historical call sites needed exported explicitly, because the implementations they consolidate genuinely differed.
- **The native-concept taxonomy is stated once.** The three copies it replaces had drifted; each call path's observable behaviour is preserved exactly and the drift is recorded in the module header and pinned by tests. See [docs/derivation-swap.md](docs/derivation-swap.md).
- **The url-bearing-object test says what it does.** It reduces to `Boolean(schema.properties?.url)`; the code now states that rather than implying a narrower check it never performed.
